# APP #1: LeanLife — Overvekt & Vekthåndtering

**Denne appen er HØY PRIORITET og leveres med full implementeringsplan.**

---

## 1. Toppopplysninger

- **App-navn:** LeanLife
- **Domeneforslag:** leanlife.app / getleanlife.com
- **Tagline:** «Din personlige vei til varig, sunn vekt.»
- **Elevator pitch (30 ord):** LeanLife kombinerer AI-drevet kaloritracking, personlige måltidsplaner, treningsforslag og atferdscoaching for å hjelpe overvektige med å oppnå varig vekttap — motivert av vitenskap, ikke skam.
- **Problemkort:**
  - **Hva:** Over 2 milliarder mennesker er overvektige (WHO). Fedme øker risikoen for diabetes type 2, hjertesykdom, kreft, leddproblemer og depresjon.
  - **Hvem rammes:** Voksne 25–65 år i alle land; spesielt økende blant barn og unge. Kvinner og lavere inntektsgrupper er overrepresentert.
  - **Omfang:** 2,5 mrd. overvektige (BMI ≥25), 890M med fedme (BMI ≥30). Kostnad: ~$2 billioner/år globalt i helseutgifter og produktivitetstap.

## 2. Produktoversikt

### 2.1 Hovedidé og kjernefunksjoner

**Must-have (MVP):**
1. Brukerregistrering med helseprofil (høyde, vekt, mål, alder, kjønn, aktivitetsnivå)
2. Daglig kalori- og makrosporing (søk, strekkode-skanner, foto-AI)
3. Personlig kaloribudsjett basert på mål (tap 0,5–1 kg/uke)
4. Vektlogg med graf og trendanalyse
5. Måltidsplanlegger med ukentlige forslag (AI-generert)
6. Treningsforslag tilpasset nivå og preferanser
7. Daglig sjekk-in og motivasjonsnotifikasjoner
8. Dashboard med fremgang, streaks og badges

**Nice-to-have (v2):**
1. Integrasjon med Apple Health / Google Fit / Fitbit
2. Foto-basert matgjenkjenning med AI
3. Sosiale funksjoner: utfordringer, accountability-partner
4. Oppskriftsbibliotek med næringsinnhold
5. Profesjonell kobling: ernæringsfysiolog/personlig trener
6. Fastefunksjoner (intermittent fasting tracker)
7. Kroppsmålinger (midje, hofte, etc.)
8. Eksport av data til lege/helsepersonell

### 2.2 Målgruppe og brukerpersonaer

**Persona 1: «Marie, 34»**
- Mamma, kontorjobb, BMI 29
- Mål: Gå ned 12 kg før sommeren
- Smertepunkter: Ikke tid til å lage mat fra bunnen; orker ikke kaloritelling; har prøvd mange dietter
- Behov: Enkle, raske måltidsforslag; motivasjon gjennom små seire

**Persona 2: «Erik, 47»**
- Sjåfør, BMI 33, pre-diabetiker
- Mål: Redusere vekt for å unngå diabetes
- Smertepunkter: Spiser mye ute; vet ikke hva som er «sunt»; legen har advart ham
- Behov: Restaurant-vennlig sporingsverktøy; enkel visualisering av fremgang; påminnelser

**Persona 3: «Sara, 22»**
- Student, BMI 27, emosjonell spising
- Mål: Etablere sunne vaner og gå ned 8 kg
- Smertepunkter: Stressspising; dårlig matbudsjett; skam rundt vekt
- Behov: Ikke-dømmende tone; studentvennlige oppskrifter; mentalhelseaspekt

### 2.3 Use cases / brukerreiser

1. **Onboarding:** Marie laster ned appen → fyller ut profil → får personlig kaloribudsjett → ser sin første ukesplan.
2. **Daglig logging:** Erik tar bilde av lunsj → AI gjenkjenner salat med kylling → kalorier logges automatisk → han ser gjenværende budsjett.
3. **Vektsjekk:** Sara veier seg mandag morgen → logger vekt → ser 4-ukers trend → får oppmuntring for 1,5 kg nedgang.
4. **Treningsforslag:** Marie åpner «Trening»-tab → får 20-minutters HIIT for hjemme → markerer som fullført → kaloriforbrenning legges til.
5. **Ukentlig oppsummering:** Erik mottar push-notifikasjon søndag → ser ukens sammendrag → feirer streak → deler fremgang med kone.

### 3.3 API-design (REST)

**Base URL:** `https://api.leanlife.app/v1`

#### Endepunkter:

**Auth:**
```
POST /auth/register     → { email, password, name }  → { token, user }
POST /auth/login        → { email, password }         → { token, refreshToken }
POST /auth/refresh      → { refreshToken }            → { token }
DELETE /auth/logout      → {}                          → { success }
```

**Profile:**
```
GET  /profile           → { user with healthProfile }
PUT  /profile           → { height, weight, goalWeight, activityLevel, birthDate, sex }
```

**Food Logging:**
```
POST /food/log          → { foodId, amount, mealType, date }  → { logEntry }
GET  /food/log?date=    → [ logEntries with nutrition ]
DELETE /food/log/:id    → { success }
GET  /food/search?q=    → [ foodItems ]
POST /food/scan         → { barcode }  → { foodItem }
POST /food/photo        → multipart/form-data  → { foodItem, confidence }
```

**Weight:**
```
POST /weight            → { weight, date }  → { entry }
GET  /weight?from=&to=  → [ entries ]
GET  /weight/stats      → { current, start, goal, trend, weeklyChange }
```

**Meals:**
```
GET  /meals/plan?week=  → { weekPlan with meals }
POST /meals/generate    → { preferences, restrictions }  → { weekPlan }
GET  /meals/:id         → { meal with recipe, nutrition }
```

**Exercise:**
```
GET  /exercise/suggest  → [ exercises based on profile ]
POST /exercise/log      → { type, duration, calories }  → { entry }
GET  /exercise/log?date= → [ entries ]
```

### 3.5 Sikkerhet og personvern

- **Autentisering:** JWT med korte access tokens (15 min), refresh tokens (30 dager) i httpOnly cookies
- **Passord:** bcrypt med cost factor 12
- **Transport:** TLS 1.3 overalt (HTTPS-only)
- **Data-kryptering:** AES-256 for sensitive helserelaterte data at rest
- **GDPR-compliance:**
  - Dataminimering: kun nødvendige data samles
  - Rett til sletting: fullstendig konto- og datakaskade-sletting
  - Dataportabilitet: eksport i JSON/CSV
  - Samtykkelogg: alle samtykker tidsstemplet
  - DPA med alle tredjepartstjenester
- **Rate limiting:** 100 req/min per bruker, 10 req/min for auth-endepunkter
- **Input-validering:** Zod-schema-validering på alle endepunkter
- **Logging:** Strukturert logging (Pino), ingen PII i logger
